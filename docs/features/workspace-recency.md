# 功能：工作区最近更新排序与置顶

- 功能 id：`workspace-recency`
- 默认状态：启用
- 可调参数：`reconcileSeconds`（默认 `60`，安全重排周期）

## 做什么

侧栏工作区不再是固定的插入顺序，而是按与会话列表「最近更新」相同的规则排序：

1. **置顶分区**在最前；
2. 置顶分区内、以及其余工作区，都按组内会话的**最近活动时间**倒序；
3. 没有任何活动的工作区回退到自身的 `updatedAt`；时间相同时按 id 稳定排序。

统计时排除已归档会话。顺序写入 Host 的持久工作区注册表（`workspaceRegistry.insertBefore`），所以内置侧栏直接按这个顺序渲染，**没有替换任何内置槽位**。

## 怎么置顶

- 在工作区行上**右键**，或展开该行后点「⋯」菜单 —— 两个入口打开同一个菜单；
- 菜单里多一项 **置顶工作区 / 取消置顶工作区**，图标与会话行的置顶图标是同一份 Fluent pushpin（轮廓 = 未置顶，实心 = 已置顶）；
- 操作成功后弹一个确认提示（置顶后行会移动，但不一定在视野内）。

## 数据来源

两路合一：

- 本进程看到的会话活动（`api-session/activity`、`api-session/added`）；
- 浏览器推送的完整会话时间表 —— 侧栏排序用的就是这份数据，包含本进程没激活过的历史会话。

持久状态：`<harness home>/dsh-ui-ex/workspace-recency.json`（置顶集合 + 会话最近活动时间），重启后在浏览器连上之前就能按上次的快照排好。

## 限制

- **顺序是自动的**：手动拖拽工作区只是临时结果，下一次排序（≤1 分钟，或下一条会话消息）会恢复时间序。
- 工作区行没有装饰槽位，所以置顶只体现为位置与菜单文案，**不会**像会话行那样显示行内 pin 标记。
- 「工作区树」分组下，工作区嵌套在最近的已注册祖先之下，置顶只能在本层级内排到最前。
- 需要 Host 侧 `workspaceRegistry`。注册表自己有一段异步启动（会话头索引 + 一次性历史引导），本插件加载时它通常还没就绪，所以功能**不会**因此停用：RPC 立即可用，置顶与浏览器推送的会话时间表先缓存，`ctx.inject(['workspaceRegistry'], …)` 在服务激活的那一刻开始排序并回放缓存。启动期间的置顶请求最多等 5 秒；超过 30 秒仍没有注册表才记一条警告（此时置顶不可用，其余功能不受影响）。
